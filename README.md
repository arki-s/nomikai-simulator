# 🍻 Nomikai Simulator

4人のプリセットから2〜4人とお店を選び、1クリック・1人・1行動ずつ進める飲み会シミュレーターです。Phase 1.5のローカル試作です。

## 起動

```bash
cd apps/web
npm ci
npm run dev
```

http://localhost:3000 を開きます。Next.js 16系を使用しています。開発起動・本番ビルドともWebpackを使用します。現環境ではTurbopackのCSS処理が内部ポートの作成拒否で停止したため、正常に完了したWebpackへ本番ビルドも統一しています。既存のGoogle Fonts取得にはビルド時のネットワーク接続が必要です。

AIを使う場合だけ `apps/web/.env.local` に `OPENAI_API_KEY=...` を設定してください。キーがなくても定型セリフで動作します。環境変数ファイルはコミットしないでください。AIなしで確認するときは `OPENAI_API_KEY='' npm run dev` で既存設定を変更せず起動できます。

## 操作

1. 明るい人・物静かな人・語りたがりな人・甘党な人から2〜4人を選びます。行動順は掲載順です。
2. 居酒屋・和食店・バルから店舗を選びます。各店のメニューと効果を開始前に確認できます。
3. 「飲み会開始」で酔い・満腹0、ターン0、AI試行0から開始。「何飲む？」→各自注文→待機1ステップ→全員に到着→全員同時の乾杯と進みます。開始演出は通常ターン・AI試行・飲食を消費しません。
4. 「次のターン」で1人だけが飲む・食べる・話す・休むのいずれかを行います。
5. 舞台・状態・最新イベントと、今回の累積ログを確認できます。飲食1回で1品を消費し、空の器は人物・種類別に表示。5個以上はアイコン1個＋残数へ集約します（＋5なら計6個）。「行動の理由」を開くと抽選条件と効果を確認できます。
6. 20ターンで終了します。ログと最終状態はそのまま閲覧できます。
7. 「同じ設定で再開催」は状態とログを初期化。「設定に戻る」は今回の状態とログを破棄し、直前の設定をフォームに戻します。

BGMとSEは進行操作付近で個別にON/OFFできます。初期OFF、再開催・設定画面往復では設定維持、終了・設定画面・ページ離脱では停止します。非表示タブでは停止し、復帰時はBGMだけ再開します（先頭から）。再読み込みは両方OFF。再生拒否・音源エラーは案内し、飲み会を継続します。

状態とログはブラウザのReact stateだけに保持します。再読み込み・ページ離脱で消えます。過去開催の保存はありません。DB、認証、キャラクター編集、画像アップロード、PDF、AWS、特殊イベントは追加していません。

## ルール

| 行動 | 効果 | AI |
| --- | --- | --- |
| 飲む | 飲み物の酔い効果 × 人物の酔いやすさ（四捨五入） | 呼ばない |
| 食べる | 料理の満腹効果 | 呼ばない |
| 話す | 状態変化なし | 上限未満ならセリフだけ生成 |
| 休む | 酔い−5・満腹−5 | 呼ばない |

値を0〜100の整数に収め、イベントには実際の変化量を記録します。数値はゲーム用で、医学的な指標ではありません。

基本の抽選重みは飲む3・食べる3・話す3・休む1。満腹30未満では食べる6、酔い80以上では休む6に変更。その後、人物と店舗の補正を加えます。最後に、飲める品がなければ飲む0、満腹100なら食べる0を適用し、補正で禁止行動が復活しないようにしています。休む重みは最低1です。飲み物は最初に配膳された一杯を優先し、消費後は飲酒方針で候補を絞って等確率で選びます。甘党な人はデザート重み3、その他の料理1で選びます。これは食べる行動自体の抽選とは別です。

甘党な人は成人女性のノンアル限定人物です。飲酒可能人物も酔い60以上になると、その開催中はノンアルのみ。休んでも飲酒へ戻りません。ノンアル自体は酔い・満腹を変えません。全店にビール・りんごジュース・デザートがあります。閾値60、切替継続、デザート重み3と満腹効果（居酒屋12、和食15、バル20）は調整用の仮値です。

人物特性は `characters.ts`、店舗・メニューは `venues.ts` の同梱データです。酔いやすさ・行動重み・飲酒方針・デザート嗜好を定義し、既存3人の口調を維持しています。画像は同梱SVGで、外部画像通信はありません。

## AIの責務と上限

AIは既存の `gpt-4.1-mini` とResponses APIを使用します。話者・行動・状態はアプリが確定し、AIは200文字以内のセリフだけを返します。文脈は選択参加者、店舗、話者の状態、最大6発言です。

開催ごとに**生成試行8回まで**。キー未設定・生成失敗・不正出力も1試行として数えます。失敗時と上限到達後は人物ごとの定型文で続行し、理由を画面に表示します。実際の課金回数を表すカウンターではありません。SDK自動再試行はなし、AI待機は10秒、ブラウザの通信待機は20秒です。

入力・出力の形式は検証しますが、サーバーは開催状態を保存しません。**状態改変・複数タブ・応答消失後の手動再送まで含めた厳密な課金上限や重複防止は保証しません。** 通信失敗時は画面の状態とログを維持し、自動再送しません。再試行で抽選やセリフが変わる場合があります。

## コードの責務

配置は `apps/web/features/nomikai/` です。

- `types.ts`：共有型・上限
- `characters.ts` / `venues.ts`：固定人物・店舗・メニュー
- `simulation.ts`：開催初期化、行動順、画面内のログ集約
- `rules.ts`：抽選・飲食物選択・状態計算・理由（乱数を注入可能）
- `opening.ts`：定型の開始進行・注文・全員乾杯
- `vessels.ts` / `components/EmptyVessels.tsx`：ログから器の集計・表示
- `audio-controller.ts` / `use-nomikai-audio.ts`：音声の独立したON/OFF・重複防止・停止・障害処理
- `validation.ts`：API入力と応答の整合性検証
- `server/advance-turn.ts`：1ターン進行、AI試行上限、定型文への切り替え
- `server/generate-dialogue.ts`：AI通信・セリフ検証
- `use-nomikai.ts`：React state、通信、連打防止、再開催
- `components/`：開催設定、舞台、状態、最新イベント、累積ログ
- `apps/web/app/api/nomikai/route.ts`：HTTP受付・応答

最新イベントとAI向け直近発言は、累積ログから取り出します。履歴を重複管理せず、成功したターンの状態とログをまとめて更新します。

## API

`POST /api/nomikai`

入力は `{ state: { config, turn, openingStep, aiAttempts, participants }, recentSpeeches }`、出力は `{ state, events }`。応答のeventsは今回のターン分のみです。

- `config`：`{ participantIds, venueId }`。人物IDは `youkya` → `inkya` → `preacher` → `sweet_tooth` の掲載順から2〜4人。店舗IDは `izakaya` / `washoku` / `bar`。
- `participants`：選択した人物IDだけをキーとする `{ drunkenness, fullness, nonAlcoholOnly, firstDrinkId }` のマップ。
- `openingStep`：確定した開始ステップ数（0〜人数＋4）。画面の開始操作で質問の1ステップをローカル確定し、以降は同じPOST APIで進めます。
- `turn`：完了ターン数。開始時0、上限20。
- `aiAttempts`：生成試行数。開始時0、上限8。
- `events`：開始中は`opening`イベント1件（`step`、`stage`、`speakerIds`、`text`、注文時のみ`menuItemId`）。通常は行動1件と、話す場合のみ発言1件。飲食行動には店舗内の `menuItemId` を含む。
- 発言の `source` は `ai` / `fallback`。後者は `fallbackReason` が `unavailable` / `budget_exhausted`。

正常・AI失敗・AI上限到達は200。不正入力400、ターン終了後409、本文上限超過413、予期しないエラー500。GETは405です。

## 検証

```bash
cd apps/web
npm test
npm run typecheck
npm run lint
npm run build
```

自動テストはNode標準テスト＋tsxです。AI通信はモックに差し替え、実際のAPIキーを使いません。参加者全11組合せ×3店舗の開始演出と20ターン完走、上限前後、AI失敗、状態範囲、入力検証、非行動者の不変性、ログの蓄積、同梱画像参照を確認します。

ブラウザでの確認項目：人数不足時の開始禁止、参加者・店舗選択、1人ずつの進行、飲食物名とメーターの一致、発言後の吹き出し解除、累積ログ、20ターン終了、AI上限、再開催・設定変更、連打防止、通信失敗時の状態維持、再読み込みでの初期化、スマートフォン幅とキーボード操作。

## 音源

ユーザー提供ファイルを `apps/web/public/nomikai/audio/` から配信します。元ファイル名と各 `利用元.md` を維持しています。BGMは居酒屋344_BPM120、和食店220_BPM86、バル032_BPM160。SEは飲む・食べる・全員乾杯に1回ずつ。20ターン終了時は停止を優先し、最終ターンのSEも再生しません。
