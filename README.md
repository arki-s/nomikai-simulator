# 🍻 Nomikai Simulator

固定3人の飲み会を、1クリック・1人・1行動ずつ進めるシミュレーターです。

## 起動

```bash
cd apps/web
npm ci
npm run dev
```

[http://localhost:3000](http://localhost:3000) を開きます。Next.js 16.2.1の実行にはNode.js 20.9以上が必要です。依存ツールの互換性も考慮し、開発環境では対応するLTSの新しいパッチ版を使用してください。

AIを使う場合だけ `apps/web/.env.local` に `OPENAI_API_KEY=...` を設定してください。キーがなくても定型セリフで動作します。環境変数ファイルはコミットしないでください。

開発起動はWebpackモードを使用します。現環境のTurbopack開発モードでは、Tailwind CSSを親ディレクトリから解決しようとして画面を開けないためです。本番ビルドは標準の `next build` を維持しています。

## 操作

1. 「飲み会開始」で酔い・満腹が0の状態を作ります。
2. 「次のターン」を押すと、陽キャ→陰キャ→説教おじさんの順に1人が行動します。
3. 状態メーターと、そのターンの出来事・セリフを確認できます。
4. 20ターンで終了します。「もう一度開催」で初期化できます。途中の「最初からやり直す」も状態を初期化します。

状態はブラウザのReact stateだけに保持します。再読み込み・ページ離脱で消えます。DB、認証、画像アップロード、PDF、AWSは使用していません。

## 最小版のルール

| 行動   | 酔い | 満腹 | AI             |
| ------ | ---: | ---: | -------------- |
| 飲む   |  +10 |    0 | 呼ばない       |
| 食べる |    0 |  +15 | 呼ばない       |
| 話す   |    0 |    0 | セリフだけ生成 |
| 休む   |   -5 |   -5 | 呼ばない       |

値は0〜100に制限し、出来事には実際に変化した量を表示します。通常の抽選重みは飲む3・食べる3・話す3・休む1。満腹30未満は食べる6、満腹100は食べる0。酔い80以上は飲む0・休む6です。人物ごとの行動ルールは共通で、口調が異なります。数値はゲーム用で、医学的な指標ではありません。

AIは `gpt-4.1-mini` のResponses APIを使用し、確定した話者のセリフだけを生成します。状態・行動はルールが決めます。文脈は最大6発言、セリフは200文字以内です。キー未設定・生成失敗・不正出力では、人物ごとの定型文で続行し、画面に明示します。API待機は10秒、SDK自動再試行なし。ブラウザの通信待機は20秒です。

## コードの役割

- `apps/web/features/nomikai/types.ts`：共有する型と上限
- `characters.ts`：固定人物と独立した初期状態
- `rules.ts`：重み付き行動選択と状態変化（乱数を注入可能）
- `validation.ts`：API入力と画面が受け取る応答の検証
- `server/advance-turn.ts`：1ターンの進行と定型文への切り替え
- `server/generate-dialogue.ts`：OpenAIとの通信と出力検証（APIからのみ利用）
- `use-nomikai.ts`：通信・React state・連打防止
- `components/`：参加者状態と最新イベントの表示
- `apps/web/app/api/nomikai/route.ts`：HTTPの入出力

ルール、外部通信、表示を分けることで、AIなしで状態変化を検証できます。状態更新が成功したときだけ、画面の状態とイベントを同時に差し替えます。

## API

`POST /api/nomikai`

入力は `{ state: { turn, participants }, recentSpeeches }`、出力は `{ state, events }`。`turn`は完了したターン数で、初期値0です。人物IDは `youkya`、`inkya`、`preacher`。各人物の状態は `{ drunkenness, fullness }` です。

- 正常：200
- JSON・状態・文脈の不備：400
- 20ターン完了後：409
- 大きすぎる本文：413
- 予期しない進行エラー：500
- 旧GETの一括会話生成は廃止：405

認証もサーバー側の状態保存もありません。入力の形式・範囲は検証しますが、過去状態の改ざんやAPIの呼び出し回数は保証しません。ローカル試作用であり、公開運用前にはアクセス制御・費用上限が必要です。通信失敗時は画面の状態を維持し、自動再送しません。手動再試行で抽選・発言が変わることや、AI料金が再発生することがあります。

## 検証

```bash
cd apps/web
npm test
npm run typecheck
npm run lint
npm run build
```

自動テストはNode標準テスト＋tsxで実行します。AI生成器を差し替えるため、APIキー・外部AI通信は不要です。行動効果、抽選の境界、状態範囲、入力検証、AI非依存、定型文への切り替え、20ターン完走を確認します。

手動確認：開始→進行→20ターン終了→再開催、連打防止、通信失敗時に状態が進まないこと、再読み込み時の初期化。AIなしの確認ではシェルで `OPENAI_API_KEY='' npm run dev` とすると既存のローカル設定を変更せずに起動できます。
